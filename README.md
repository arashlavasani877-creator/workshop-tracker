# افراچوب — نسخه ۳ (اصلاح ورود + هشدار جدا + توضیحات + نصب صفحه کابینت)

## چیزهایی که این نسخه اصلاح/اضافه کرد
1. **رفع مشکل ورود با گوگل**: روش ورود از پنجره‌ی بازشو (popup) به روش redirect تغییر کرد که روی مرورگرهای موبایل مطمئن‌تر است.
2. **تایید کاربر با تعیین نام و سمت**: وقتی مدیر روی «تایید و تعیین سمت» بزند، یک پنجره باز می‌شود تا نام و سمت فرد را بنویسد؛ بعد از تایید، آن فرد بلافاصله وارد اپ می‌شود.
3. **صفحه‌ی جدا «هشدار سررسید»**: هم برای مدیر و هم برای سرپرست، به‌صورت یک تب جداگانه (نه داخل صفحه‌ی قراردادها).
4. **فیلد توضیحات**: بالای تاریخچه‌ی هر قرارداد، همه (مدیر و سرپرست) می‌توانند یادداشت بنویسند.
5. **تاریخچه جمع‌شونده**: با کلیک روی «تاریخچه ▼» باز/بسته می‌شود؛ برای مدیر پیش‌فرض باز، برای سرپرست پیش‌فرض بسته.
6. **دکمه «نصب صفحه کابینت»**: در مرحله‌ی «در حال نصب»، تا این دکمه زده نشود، درصد پیشرفت آن مرحله نمی‌تواند از ۸۰٪ بیشتر شود (این محدودیت هم در صفحه و هم در پایگاه‌داده اعمال می‌شود).
7. **سررسید اصلی فقط با مدیر**: سرپرست فقط می‌تواند «سررسید جبرانی» را وارد کند؛ هر تغییر با نام حساب‌کاربری و زمان در تاریخچه ثبت می‌شود.

## فایل‌هایی که باید در GitHub جایگزین شوند
`index.html`, `app.js`, `service-worker.js` — همین سه فایل کافیست (بقیه دست‌نخورده‌اند).

**روش:** Add file → Upload files → این ۳ فایل را انتخاب کنید → Commit changes.

## مرحله‌ی ضروری — انتشار مجدد قوانین Firestore
چون قوانین امنیتی هم سخت‌گیرانه‌تر شده (فقط مدیر می‌تواند قرارداد بسازد/حذف کند یا سررسید اصلی و کد قلم را عوض کند):
1. Firebase Console → Build/Databases and storage → Firestore Database → تب **Rules**
2. تمام متن را پاک کنید، متن جدید فایل `firestore.rules` را جای‌گذاری کنید
3. **Publish**

## نکته‌ی مهم برای خودتان و سرپرست، بعد از هر آپدیت
بعد از اینکه فایل‌های جدید را در GitHub آپلود کردید، هرکسی که اپ را قبلاً نصب/باز کرده باید:
- اپ را کامل ببندد (نه فقط برگردد) و دوباره باز کند — معمولاً همین کافیست
- اگر بعد از یک دقیقه هنوز تغییری ندید: تنظیمات Chrome → Privacy → Clear browsing data → فقط «Cached images and files» و «Cookies and site data» → Clear، بعد اپ را دوباره باز کند

## یادآوری از قبل
- ورود با گوگل و Authorized domains باید از قبل فعال باشند (در README نسخه‌ی قبلی توضیح داده شده بود).
- VPN/فیلترینگ همچنان یک عامل خارج از کنترل کد است؛ اگر مشکلی دیدید، ابتدا Incognito را تست کنید تا مشخص شود مشکل کش است یا شبکه.
