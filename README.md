# افراچوب — راهنمای نسخه‌ی جدید (ورود، نقش‌ها، داشبورد)

## چیزهایی که این نسخه اضافه کرد
- ورود با حساب گوگل (هرکس بدون تایید شما، فقط پیام «در انتظار تایید» می‌بیند)
- شما (arashlavasani891@gmail.com) به‌صورت خودکار «مدیر» هستید
- صفحه‌ی مدیریتی جدا: داشبورد گزارش + مدیریت کامل کاربران (تایید / لغو دسترسی / مسدودکردن / حذف)
- فقط مدیر می‌تواند قرارداد اضافه یا حذف کند، یا «کد قلم» ثبت کند
- سرپرست نصب فقط می‌تواند مراحل را ثبت کند و تاریخ سررسید قرارداد را وارد کند
- سررسید هر قرارداد (شمسی)، وضعیت رنگی (سبز/زرد/قرمز)، و «جلوتر/عقب‌تر از برنامه»
- وقتی سررسید گذشت، مدیر می‌تواند «سررسید جبرانی» وارد کند؛ گزارش بعدش بر اساس هر دو تاریخ است
- برای سرپرست، بالای صفحه لیست هشدار «سررسیدهای نزدیک/گذشته» نمایش داده می‌شود
- آیکون و اسم اپ به لوگوی افراچوب تغییر کرد

## فایل‌هایی که باید در GitHub جایگزین شوند
همه‌ی این فایل‌ها عوض شده‌اند — همه را در همان ریپازیتوری قبلی (`workshop-tracker`) دوباره آپلود کنید:
`index.html`, `app.js` (فایل تازه)، `manifest.json`, `firebase-config.js`, `service-worker.js`,
`icon-192.png`, `icon-512.png`, `icon-maskable-512.png`

**روش:** در صفحه‌ی اصلی ریپازیتوری، Add file → Upload files → همه‌ی فایل‌های پوشه را دوباره بکشید/انتخاب کنید. GitHub خودش فایل‌های هم‌نام را جایگزین می‌کند. پایین صفحه Commit changes را بزنید.

## مرحله‌ی ضروری ۱ — فعال‌سازی ورود با گوگل
1. در Firebase Console پروژه‌ی afrachub، از منو بروید به Build → Authentication
2. تب Sign-in method → Add new provider → Google
3. Enable کنید، ایمیل پشتیبانی را انتخاب کنید (همان جیمیل خودتان) → Save

## مرحله‌ی ضروری ۲ — اضافه‌کردن دامنه‌ی مجاز
1. همان صفحه Authentication → تب Settings → Authorized domains
2. Add domain بزنید و آدرس گیت‌هاب‌پیجز خودتان را بدون https:// وارد کنید، مثلاً:
   arashlavasani877-creator.github.io

(بدون این مرحله، دکمه‌ی ورود با گوگل خطا می‌دهد.)

## مرحله‌ی ضروری ۳ — قوانین امنیتی Firestore
1. Build → Firestore Database → تب Rules
2. تمام محتوای فعلی را پاک کنید و محتوای فایل firestore.rules (داخل همین پوشه) را جای‌گذاری کنید
3. Publish را بزنید

این قوانین همان چیزی است که خواستید: فقط مدیر می‌تواند نقش افراد را عوض کند؛ کاربر تازه‌وارد فقط می‌تواند خودش را «در انتظار تایید» بسازد، نه مدیر یا سرپرست؛ کاربر تاییدنشده اصلاً به هیچ داده‌ای دسترسی ندارد.

## نکته درباره «حذف کامل دسترسی»
با ابزار رایگان (بدون سرور اضافه)، وقتی کسی را «مسدود» یا «حذف» می‌کنید، او هیچ اطلاعاتی نمی‌بیند و نمی‌تواند چیزی تغییر دهد — دسترسی واقعی‌اش صفر می‌شود. فقط حساب گوگلش هنوز می‌تواند صفحه‌ی ورود را باز کند و پیام «مسدود شده» ببیند (غیرفعال‌کردن کامل حساب در سطح گوگل نیاز به سرویس اضافه با پلن پولی دارد). از نظر امنیت داده، نتیجه یکسان است.

## نکته‌ی صادقانه درباره VPN و اینترنت ایران
Firebase و GitHub Pages زیرساخت گوگل و گیت‌هاب هستند. هیچ تغییری در کد نمی‌تواند تضمین کند این سرویس‌ها همیشه بدون فیلترشکن در ایران در دسترس باشند — این به وضعیت فیلترینگ کشور بستگی دارد که مستقل از این اپ و متغیر است. بعد از راه‌اندازی از یک خط بدون فیلترشکن تست کنید؛ اگر مشکل بود بگویید تا گزینه‌های جایگزین (میزبانی دیگر یا لایه‌ی واسط) را بررسی کنیم — تضمین قطعی از پیش ممکن نیست.
